## Cambios técnicos de v1.4.11

### `attemptToggle` simplificado

Antes (v1.4.10): removía el service de la lista, lo re-añadía, y
finalmente hacía flag 0 → 1. Esto confundía al `AccessibilityManagerService`
de OLAX porque "veía" la misma lista antes y después.

Ahora (v1.4.11): **solo flag 0 → 1, sin tocar la lista**. La lista ya
tiene nuestro service (de `--setup`), entonces el system ve un cambio
de estado (no de contenido) y re-bindea correctamente.

```kotlin
private fun attemptToggle(attempt: Int): Boolean {
    val cr = contentResolver
    Settings.Secure.putInt(cr, Settings.Secure.ACCESSIBILITY_ENABLED, 0)
    Thread.sleep(VERIFY_DELAY_MS)
    // verify
    Thread.sleep(A11Y_TOGGLE_DELAY_MS)
    Settings.Secure.putInt(cr, Settings.Secure.ACCESSIBILITY_ENABLED, 1)
    Thread.sleep(VERIFY_DELAY_MS)
    // verify
    return true
}
```

### `startToggleSequence` con un solo toggle + grace

Antes (v1.4.10): hacía segundo toggle después de verificar el primero.
Eso **no funcionó** — el service seguía sin bindearse.

Ahora (v1.4.11): un solo toggle + `BIND_GRACE_MS = 5000L` (5s) de espera
antes del `moveTaskToBack`. Eso le dio tiempo suficiente al
AccessibilityManagerService para bindear.

## El bug de `WRITE_SECURE_SETTINGS` (descubierto en este test)

**Síntoma**:
```
java.lang.SecurityException: Permission denial: writing to settings
requires:android.permission.WRITE_SECURE_SETTINGS
at com.miro.a11y.MiroLauncherActivity.attemptToggle(MiroLauncherActivity.kt:184)
```

**Causa**: `pm grant` solo se aplica al package actual. Si hacés
`uninstall + install` (incluso entre versiones del mismo APK firmado
con la misma keystore), el grant **se pierde**.

**Fix en `adb_tablet --setup`**: el `--setup` ya hace
`pm grant com.miro.a11y android.permission.WRITE_SECURE_SETTINGS`.
Pero si la app crashea durante `--setup` (por ejemplo, si HOME no está
seteada todavía), el grant queda sin verificar.

**Mejora propuesta**: `--setup` debe **verificar el grant** después
de hacerlo, y si está en false, re-grantearlo. También debería
re-grantear el permission automáticamente en cada `--recover` o cada
post-reboot si la app está instalada.
